# 旧版任务的完整启动证明与安全退役

适用于没有 `lockProtocol:2` 的 0.4.2 已接管任务。没有无条件强制解锁按钮，不会自动重启 Windows，也不会终止正在运行的任务。

## 用户操作

1. 查看独立助手，等待真实活动任务完成。不要手动删除锁或 ZIP。
2. 在 Packer 点击“检查并恢复异常任务”。若旧任务之后没有完整系统启动，保存工作并通过 Windows“重新启动”，随后再检查。普通关机可能使用快速启动；休眠、睡眠、等待超时都不构成证明。
3. 证据充分时，页面展示任务 ID、任务记录时间与完整启动时间，原锁此时尚未移动。
4. 点击“确认安全退役此旧任务（保留全部证据）”。Packer 重新检查全部条件，成功后才能用新 ZIP 名称重新备份。旧备份仍为未确认，不自动宣称 ZIP 有效。
5. 任一证据损坏、缺失、变化或无法查询，都继续拒绝，并显示具体原因。不得靠删除依赖声明或关闭安全检测让重试通过。

## 充分条件是联合证明

- 限本机固定 NTFS 磁盘；锁、任务目录及记录路径不能经过 reparse/junction。
- 六份必要记录 `job / launched / ready / worker-ready / accepted / status` 的任务 ID、UI/协调器 PID 关系及旧协议字段一致。无完整交接链的历史任务拒绝恢复。
- 本机 Kernel-Boot 27 和 Kernel-General 12 的已识别模板、启动类型/模式、启动时间，与 `Win32_OperatingSystem.LastBootUpTime` 相互吻合。未知事件版本拒绝。BootType 字段是附加保守筛选，不单独作为证明。
- 文件创建/修改时间、目录创建时间和状态时间均须早于启动至少两分钟。余量用于限制时钟与查询误差；这不是“等两分钟就能删锁”。
- 按事件记录序号收集启动后的时钟调整，累计绝对调整超过 15 秒即拒绝，不能用相互抵消的净变化掩盖回拨。再用单调 TickCount 核对启动至今的时长，差异超过 30 秒拒绝；运行超过 49 天或计时歧义拒绝旧协议恢复。
- 完整当前进程查询成功；记录 PID 的复用只能属于当前启动后的其他进程。仍引用旧任务的进程、任意受支持的旧冷任务组件（包括相对任务路径启动）、候选进程缺命令行/创建时间，都拒绝。

完整启动意味着旧用户态任务不能保持原来的进程生命周期；但时间戳或 PID 单独不能确认这一点。以上组合是在未被管理员或同一用户刻意篡改任务文件/系统日志、使用受支持启动脚本的故障模型下的保守证明。不是对恶意同权限代码的安全边界。

## 并发与原子退役

根 `operation.guard` 排他内核句柄覆盖检查与退役。第二步确认绑定任务 ID；锁换成其他任务时拒绝旧确认，包含换成新协议任务的情形。

最终核验时独占读取旧 `job.json`（FileShare.None），并以共享只读句柄保护其他必要记录和锁。此前已初始化的进程必须在当前进程查询中不存在；之后启动的旧脚本不能再读取 job，避免检查与清理间隙重新初始化。最终退役由**持有根操作句柄的同一进程**执行防覆盖 File.Move，将 active.lock 原子移动为任务内 recovered.lock。

先落盘独立的唯一命名证明日志、恢复标记与取消围栏，保留原记录内容、日志和所有 ZIP。过程中失败或中断，可能留下尚未退役的锁和恢复证明；再次检查仍需完整重验，不能靠证明日志跳过门禁。内部桥异常退出不会赋予 Node 父进程直接删除锁的能力。

## 当前限制

没有完整启动之后的证据，就不会处理本次真实 0.4.2 旧锁。检查逻辑可自包含运行在 Packer 中，不需要 Agent。部署仍需单独验收；本候选不主动处理正式锁。

宿主提供的 peer 与 Profile 载荷依赖如何共同验证是另一个问题。当前完整性门禁仍可能报告 TRANSITIVE_DEPENDENCY_MISSING；恢复锁不等于解决该载荷兼容性问题。必须连同恢复端验证共同设计，不能把 peer 一概忽略。

## 平台依据

- Microsoft 对[系统电源状态](https://learn.microsoft.com/en-us/windows/win32/power/system-power-states)区分完整启动、快速启动与休眠。
- [Win32_OperatingSystem](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-operatingsystem) 提供系统启动时间。
- [GetTickCount](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount) 是启动后的计时值，存在约 49.7 天回绕，因此本候选对旧锁采用更保守的 49 天范围。
- Kernel-Boot 的模板版本与字段在本机 provider 元数据中核验；不把未文档化的单个事件数值当成跨 Windows 版本永久稳定的独立接口。
